## 우선순위와 해석

과제 원문의 업무 요구사항을 최상위 기준으로 삼고, 실제 컬럼·코드·업무 구현은 중간발표, 최신 테이블 정의서와 ERD v1.5, 생성 SQL을 기준으로 삼았습니다. 첨부된 초기 요구사항 문서와 HWP/PPT는 변경 전 설계이므로 무조건 모두 합치지 않았습니다. 이후 받은 최신 공유 시트의 가정사항·요구사항은 ERD v1.5·SQL과 일치하여, 해당 시트의 확정 요구사항을 화면과 조회 규칙에 반영했습니다.

| 차이 | 채택한 기준 | 이유 / 팀 확인 사항 |
| --- | --- | --- |
| 12개 vs 5개 테이블 | 5개 테이블 | 실제 생성 SQL과 중간 발표가 동일 |
| 다회 재투입 vs 1회 | 동일 프로젝트 1회 연속 투입 | 첨부 초기 문서와 달리 최신 공유 시트의 PAR-002/SRH-003에서 재투입 제외가 확정됨 |
| 개발자만 vs 모든 직군 | 모든 직군 참여 | 최신 테이블 정의서와 seed의 마케팅·연구개발 참여 반영 |
| 기술 사전 vs 텍스트 | skill_description | 복수 키워드 AND 검색. 표준화된 기술 토큰이 아니므로 자유문장 부분 일치 |
| 프로젝트 계획 | 실제 착수한 프로젝트만 등록 | 최신 명세에서 actual_start_date는 실제 착수일. 과거 시점에서는 착수 전으로 계산 가능 |
| 계획 투입기간 | 저장하지 않음 | NULL 시작/종료는 투입 전, 시작만 있으면 투입 중 |
| 종료 시점 | actual_end_date 기준 | planned_end_date 경과로 자동 종료하지 않음 |
| 임시저장 vs 완성 평가 | 완성 평가만 등록 | 최신 EVALUATION의 네 평가 필드 NOT NULL, 두 의견 공백 불가 |
| 고객 담당자 | CLIENT의 현재 대표 담당자 한 명 | 변경 시 과거 고객평가 조회에도 현재 담당자 표시. 이력 보존은 향후 별도 설계 필요 |
| 날짜 속성 _ON vs _DATE | SQL의 _date | 표준용어 파일 일부 _ON 표기가 ERD/SQL과 달라 정리 필요 |
| 학력·경력 NULL 허용 | 필수값 | 최신 SQL NOT NULL, 경력 0 이상 |

## 화면 구현 기준

- 실제 기준일은 Asia/Seoul의 오늘이며, 현황과 투입 이력에서 과거 날짜를 고를 수 있습니다. 화면 수치를 크게 보이게 하려고 임의 프로젝트나 인원을 더하지 않았습니다.
- 기간 조회는 겹치는 구간을 찾고, 투입 시작일/종료일은 당일 포함입니다. 현재 재직 상태 이력이 없으므로 과거 인원 집계는 현재 재직 상태로 필터링하지 않습니다.
- 신규 투입은 ACTIVE 직원만 허용합니다. 휴직·퇴사자의 과거 이력은 유지합니다.
- 프로젝트·발주처 신규 등록은 경영진, 프로젝트 수정·구성원 관리는 경영진 또는 해당 PM으로 가정했습니다. 타 직원 인적 정보 수정 권한은 부여하지 않습니다.
- 프로젝트 종료 시 진행 중인 실제 투입의 종료일도 함께 기록합니다. 투입 전 구성원은 실제 참여자가 아니므로 평가 대상에서 제외합니다.
- 고객평가는 먼저 의뢰일이 있어야 입력할 수 있습니다. 전체 회수는 모든 실제 참여자의 고객평가를 등록한 뒤 가능하며, 회수일은 모든 평가일 이후로 검증합니다. 회사 보고 후 고객평가 추가를 차단합니다.
- 2026-11-12 회원가입 재검토: 경영진·PM·일반 직원 선택, 학력 5개 선택, 주민번호 입력·형식 검사, 비밀번호 실시간 일치 확인을 반영했습니다. ID 중복 확인과 가입 시 재확인, 사번 자동 발급을 유지합니다. 첫 방문은 로그인 화면이며 체험 계정 버튼·데모 안내·계정 전환 메뉴를 제거했습니다.
- 가입 유형 PM은 사용자 요청에 따라 추가한 값입니다. 기존 system_role의 2개 코드와 다르므로 백엔드 연동 시 코드·DB 제약 조정이 필요합니다. 프로젝트별 PM 권한은 PROJECT_MEMBER의 PM 배정으로 검사합니다.
- 주민번호 원문은 입력 검증에만 사용하며 브라우저에는 앞 6자리와 마스킹 값만 저장합니다. 원문 암호화·DB 저장은 백엔드 연동 범위입니다. SQL의 암호화값·비밀번호 해시는 번들에서 제외했습니다.
- 인센티브·인사고과 점수는 만들지 않고 경력과 평가 원점수·의견만 CSV로 제공합니다.

## 백엔드 협의 우선순위

1. 최신 공유 시트에서 확정한 재투입·계획 투입기간 제외 및 조회 권한을 최종 보고서와 서버 구현에 동일하게 적용합니다.
2. 현재 담당자만 남기는 고객평가 이력 정책을 최종 보고서에 명시합니다.
3. 사번 발급과 고객평가 중복 방지를 DB 트랜잭션으로 설계합니다.
4. 회원가입의 입사일·직군 입력을 실제 서비스에서 누가 승인할지 합의합니다.
5. 실제 API를 연결한 뒤 권한 없는 데이터가 응답에 포함되지 않는지 통합 검증합니다.
